# Testing

`python tests/contrast.py` checks 252 text/background pairs, without rounding before comparison:

- Twelve syntax and diagnostic roles on nine normal, reference, and diff surfaces, in both variants.
- Completion label, match, kind, and detail colors on normal and selected menu surfaces.
- Dedicated visual-selection and search pairs, and all lualine mode accents.

Every tested text pair must reach 4.5:1. Visual selection must also differ from the main editor background by at least 3:1. The comments/punctuation/operators/text luminance order is tested separately. ANSI slots 1 through 15 must reach 4.5:1 against the terminal background; ANSI slot 0 is an exempt utility black. All six generated terminal ports are parsed and compared with the source palettes.

`python tools/build.py --check` detects stale generated files.

`tests/highlights.lua` runs inside Neovim. It checks module loading, setup before colorscheme activation, repeated variant changes, highlight links, Lua braces, control-flow emphasis, overrides, terminal slots, lualine colors, and the guard that prevents inactive Verdelle from restoring itself after a different colorscheme is selected.

`tests/ui.py` attaches a real RGB line-grid UI to a fresh embedded Neovim. It opens Lua, TypeScript, Python, JSON, and Markdown fixtures, then exercises visual selection, native completion with kind/source columns, diagnostic virtual text, search, side-by-side diffs, and a live background switch. It checks the composed selection colors and completion text contrast. Its PNGs render the screen cells and RGB attributes emitted by Neovim, with Pillow; they are not terminal screenshots. The CI artifacts include these images and a JSON report.

The two README specimens are designed previews generated by `tools/preview.py`. They illustrate palette roles and UI states; they do not demonstrate a live plugin session.

## Limits

Contrast is calculated from opaque sRGB palette values using WCAG relative luminance. It does not model terminal opacity, font rendering, monitor calibration, ambient light, or individual comfort.

Passive borders, indentation guides, whitespace, and line numbers have lower contrast. Diagnostic information should retain severity signs, messages, or underline styles rather than depend on hue alone.

Plugin highlight groups are defined, but individual plugin versions and custom renderers can apply additional attributes. The native completion UI is tested live; a particular blink.cmp, nvim-cmp, or Telescope setup is not thereby certified.

CI covers Neovim 0.10.4 and stable on Linux. Local Windows application control blocked the available Neovim executable during development, so live Neovim verification is performed by CI. The generated terminal configurations are checked as data; the three terminal applications are not launched by these tests.

References: [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [use of color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html), [Neovim highlights](https://neovim.io/doc/user/syntax/), [blink.cmp highlight groups](https://cmp.saghen.dev/configuration/appearance).
